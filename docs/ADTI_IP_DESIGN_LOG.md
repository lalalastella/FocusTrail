## 1. 项目定位与传播入口

- 产品品牌：FocusTrail
- 正式英文 slogan：**Attention Drifts. Here’s Direction.**
- 正式中文 slogan：**偏离之后，带你回到下一步**
- 营销钩子：**偏了吗？**
- 营销延展：**偏了吗？测测你的注意力人格。**
- 测试名称：**ADTI — Attention Drift Type Indicator**
- 中文名称：**注意力偏移人格测试**
- 核心差异：不是阻止用户分心，而是缩短用户从分心到重新行动的距离。

## 2. 测试产品构想

### 2.0 战略角色：FocusTrail 的主要营销噱头

ADTI 不是产品中的附属娱乐功能，而是 FocusTrail 冷启动阶段的**主要获客活动、校园传播话题和产品体验入口**。

统一传播结构：

- 第一眼问题：**偏了吗？**
- 行动邀请：**用一小时，测出你的注意力人格。**
- 活动名称：**偏了吗？ADTI 注意力人格测试**
- 体验产品名：**FocusTrial 1H**
- 结果承诺：**不是告诉你“自不自律”，而是呈现你如何偏离、如何启动、如何沉浸、如何回来。**
- 产品承接：**测完人格，FocusTrail 继续带你回到下一步。**

ADTI 必须同时完成三件事：

1. 用“偏了吗？”制造好奇和自我代入。
2. 通过一小时真实使用，让用户体验 FocusTrail 的核心能力，而不只是完成一份问卷。
3. 用人格结果卡制造截图、讨论、朋友对比和校园传播。

### 2.1 初期 MVP

初期测试不采用传统的 12–16 道问卷，而采用 **FocusTrial 1H**：用户实际使用本地部署的 FocusTrail 一小时，由产品采集注意力与执行轨迹并生成总结、评分和人格结果。

首期以低权限、低负担、容易解释的数据为主，重点观察：

- 偏离发生频率
- 截止线或提醒后的启动强度
- 连续沉浸时长
- 偏离后的恢复时间
- 核心任务是否继续推进
- 测试前后执行策略是否发生变化

### 2.2 长期数据构想

长期可在用户明确授权的前提下扩展：

- 电脑桌面排版与文件组织
- App 分类和切换方式
- 浏览器标签数量与类型
- AI 工具数量、类型与使用频率
- 任务、窗口和工具之间的切换轨迹

这些属于长期构想，不应增加首期测试门槛。

### 2.3 活动体验流程（MVP）

整个正式结果必须来自真实的一小时使用，不采用传统人格问卷替代。

| 阶段 | 建议时长 | 用户动作 | 产品输出 |
| --- | ---: | --- | --- |
| 钩子页 | 30 秒 | 看到“偏了吗？”并进入活动 | 建立好奇，不展示复杂理论 |
| 校准 | 1–2 分钟 | 填写本小时唯一目标和最小下一步，确认隐私权限 | 生成测试任务与本地观察范围 |
| 自然执行 | 45–50 分钟 | 使用 FocusTrail 完成真实学习、备考或求职任务 | 记录偏离、启动、沉浸、恢复和推进轨迹 |
| 回正挑战 | 穿插发生 | 当系统识别到偏离时，用户选择忽略、稍后或回到下一步 | 测量恢复时延与恢复方式 |
| 结果生成 | 3–5 分钟 | 查看四维得分、16 型结果和个性建议 | 生成人格卡、轨迹摘要和下一步建议 |
| 产品承接 | 测试结束后 | 继续执行原任务或领取校园试用权益 | 将一次性传播用户转为长期用户 |

### 2.4 首期采集与评分边界

首期只采集足够支撑人格解释的数据，不为了“显得 AI”而过度获取权限。

- **F / S**：偏离次数、切换频率、偏离时间占比。
- **B / E**：一小时内推进曲线是集中爆发还是均匀发生；可结合阶段性检查点响应，不直接假装测出长期 DDL 行为。
- **D / L**：最长连续执行时长、单任务持续性和浅切换密度。
- **R / M**：提示后的恢复时间、恢复成功率、是否回到原目标或重新定义下一步。

结果页同时展示人格代码和连续分数，避免把用户生硬地塞进绝对类别。

### 2.5 活动传播闭环

```text
“偏了吗？”内容钩子
        ↓
FocusTrial 1H 真实体验
        ↓
ADTI 四维分数＋人格 IP 结果卡
        ↓
截图分享／朋友对比／宿舍互测
        ↓
好友进入测试
        ↓
测试后的真实任务留在 FocusTrail 中继续推进
```

结果卡必须包含：

- 四字母代码和人格名
- 一个独占 IP 形象
- 一句可以被转发的人格梗
- 四维简图或四条短刻度
- “你的回正方式”一条产品建议
- 稀有度或校园内同型比例（必须来自真实样本，样本不足时不展示伪数据）
- **偏了吗？测测你的注意力人格**分享入口

### 2.6 校园推广活动形式

#### 线上：一小时偏航挑战

- 面向考研、期末周、求职投递、课程项目等真实目标。
- 用户选择一个小时任务并完成测试。
- 测试后生成可分享人格卡和“本小时回正报告”。

#### 线下：偏了吗？自习实验室

- 与校园社团、学习空间、图书馆活动或校园大使合作。
- 设置整点开测场次，降低用户独自坚持一小时的心理门槛。
- 现场只展示匿名聚合数据，例如本场平均偏离次数、平均回正时间、人格分布。
- 不公开个人“专注排名”，避免羞辱式自律和医疗化暗示。

#### 社交玩法

- 同寝室四人注意力人格图鉴
- 考研搭子／求职搭子人格互补卡
- “你负责启动，我负责把你拉回来”组合文案
- 校园人格分布地图（达到足够匿名样本后开放）
- 16 型收集图鉴与隐藏款讨论，但不公开隐藏款完整触发条件

### 2.7 免费版与 Pro 承接

ADTI 正式测试和基础人格结果应免费，不能在结果揭晓前设置付费墙。

- 校园冷启动期：完成 FocusTrial 1H 后可领取 **3 个月 Pro 试用**，用于降低首批用户付费阻力并积累长期行为样本。
- 免费版：基础任务拆解、专注计时、基础偏离提示、基础人格结果与历史摘要。
- Pro 版：个性化回正方案、提示强度定制、长期轨迹趋势、不同目标场景模型、深度周报和跨设备能力。
- 广告、赞助或机构合作不得干扰一小时测试过程；商业内容只能出现在活动权益、奖励或结果页之后。

### 2.8 核心增长指标

- “偏了吗？”落地页进入率
- 一小时测试启动率
- FocusTrial 1H 完成率
- 人格结果卡生成率与分享率
- 分享带来的好友开测率
- 测试结束后继续执行任务的比例
- D1 / D7 / D30 留存
- 三个月 Pro 试用期内的核心功能使用率
- 校园活动单个完成测试用户的获客成本
- 回正提示触发后成功返回任务的比例

### 2.9 安全与传播边界

- ADTI 是注意力与执行行为的产品化观察，不是 ADHD 诊断、医学筛查或心理疾病判断。
- 宣传中避免“测出你有没有 ADHD”“治疗注意力缺陷”等表述。
- 结果页明确标注：**仅用于自我观察与产品体验，不构成医学或心理诊断。**
- 默认优先本地处理或最小化上传，清晰解释采集内容、用途、保存时间和删除方式。
- 人格文案可以有梗，但不能羞辱用户、鼓励自我疾病标签或将某一类型描述为最优人格。

## 3. ADTI 四维模型

ADTI 名称中的四个字母同时对应四项核心能力：

- **A — Attention Drift：注意力偏移**
- **D — Deadline Drive：截止线驱动**
- **H — Hyperfocus：高沉浸能力**
- **D — Direction Recovery：方向恢复**

为了形成 16 型人格，结果代码采用四组二分档位：

- **F / S：Floating 漂移 / Stable 稳定**
- **B / E：Burst 爆发 / Even 均匀**
- **D / L：Deep 深潜 / Light 轻切**
- **R / M：Recover 回正 / Missing 迷航**

### 3.1 “ADHD”四维人格轴的正式定义

ADTI 在传播层使用容易记忆的 **A–D–H–D** 四维结构，但这里的 ADHD 只是四个产品行为维度的首字母组合，不等于医学 ADHD 诊断，也不用于判断用户是否患有 ADHD。

| 轴 | 英文名称 | 核心问题 | 连续分数含义 | 映射到人格代码 |
| --- | --- | --- | --- | --- |
| A | Attention Drift | 注意力多容易偏离当前目标？ | 分数越高，偏离和任务切换越频繁 | 高偏移＝F；低偏移＝S |
| D¹ | Deadline Drive | 行动力是截止线爆发，还是均匀推进？ | 分数越高，推进越集中于提醒、检查点或临近结束阶段 | 爆发＝B；均匀＝E |
| H | Hyperfocus | 一旦进入任务，能否持续沉浸？ | 分数越高，连续执行时间越长、浅切换越少 | 深潜＝D；轻切＝L |
| D² | Direction Recovery | 偏离以后，能否找回正确下一步？ | 分数越高，恢复越快、回到主目标的成功率越高 | 回正＝R；迷航＝M |

四字母人格代码的顺序固定为：

```text
第 1 位：A 轴 → F / S
第 2 位：D¹轴 → B / E
第 3 位：H 轴 → D / L
第 4 位：D²轴 → R / M
```

例如 **FBDR** 表示：高偏移（F）＋爆发推进（B）＋深度沉浸（D）＋能够回正（R）。

### 3.2 四维的行为观测指标

#### A — Attention Drift 注意力偏移

首期可观察：

- 单位时间任务或窗口切换次数
- 离开当前目标的累计时长
- 目标被拆成多少段不连续执行
- 无关行为出现的频率
- 从当前任务转向新刺激的速度

解释原则：高偏移不等于能力差，可能同时伴随高探索性、快速联想或更强环境敏感度。

#### D¹ — Deadline Drive 截止线驱动

首期可观察：

- 一小时内工作量是否集中在后段
- 检查点、倒计时或提醒出现后的执行增幅
- 启动前等待时间与启动后的推进速度
- 推进曲线呈“突然加速”还是“相对均匀”

解释原则：首期一小时测试只能测量短周期检查点驱动，不能直接声称已经测出用户长期面对真实 DDL 的行为。

#### H — Hyperfocus 高沉浸能力

首期可观察：

- 最长连续执行时长
- 单一核心任务的时间占比
- 深度执行区段数量
- 深度区段中的浅切换密度
- 进入状态后是否能维持任务上下文

解释原则：高沉浸不必然代表高效率，也可能出现“沉浸在错误任务中”的情况，因此必须与方向恢复轴结合解释。

#### D² — Direction Recovery 方向恢复

首期可观察：

- 偏离到重新行动的中位恢复时间
- 收到 FocusTrail 提示后的回归成功率
- 回归后是否继续原目标或明确重设下一步
- 一次恢复后能够持续执行的时间
- 偏离后是否反复进入新的无关任务

解释原则：这是 FocusTrail 最具产品差异化的核心轴。产品不要求用户永不分心，而是帮助用户缩短“偏离—识别—选择—行动”的距离。

### 3.3 分数呈现方式

四个维度都应先输出 **0–100 的连续分数**，再映射为四字母人格。结果页不能只给标签而隐藏原始倾向。

结果示例：

```text
A  注意力偏移       74  → F
D  截止线驱动       68  → B
H  高沉浸能力       81  → D
D  方向恢复         72  → R

结果：FBDR 火箭蒲公英
```

用户接近分界线时，应显示“轻度倾向”或相邻人格，而不是制造绝对判断。例如 A 轴 51 分可解释为“略偏漂移”，而不是稳定地定义为高偏移用户。

### 3.4 初版评分框架（待种子测试校准）

以下权重只作为 MVP 工程起点，不能直接包装为科学量表：

- **A 轴**：切换频率 35%＋离开目标时长 30%＋任务碎片化 20%＋无关行为频率 15%。
- **D¹轴**：后段推进集中度 35%＋提醒后执行增幅 30%＋启动延迟 20%＋推进曲线波动 15%。
- **H 轴**：最长连续时长 35%＋核心任务占比 30%＋深度区段稳定性 20%＋浅切换反向指标 15%。
- **D²轴**：恢复成功率 35%＋恢复速度 30%＋返回主目标比例 20%＋恢复后的持续执行 15%。

阈值不应凭主观固定为 50 分。建议：

1. 先收集不少于 30 次可用的一小时测试，用于发现明显的数据错误和指标失真。
2. 累积约 80–120 次有效测试后，再根据真实分布初步调整二分阈值。
3. 后续按场景分别校准，例如备考、写作、投递和编程，不假设所有任务拥有同一种注意力轨迹。
4. 持续检查 16 型分布，避免算法把大多数用户挤入少数几个类型。

### 3.5 四维解释原则

- 四个轴描述行为模式，不评价人格高低。
- 不存在“最优人格”；每种组合都必须同时给出优势、风险和可执行建议。
- 同一个人可能因任务类型、睡眠、压力和设备环境而得到不同结果。
- ADTI 的价值不是永久贴标签，而是让用户看见当前行为轨迹，并获得下一步恢复策略。
- 人格名称和 IP 可以娱乐化，底层数据解释必须克制、透明、可撤回。

## 6. MBTI / SBTI IP 研究结论

### 6.1 MBTI 类视觉的记忆机制

- 统一角色骨架
- 一个身份或职业道具
- 一个代表性动作
- 一个阵营色
- 背景弱化，依靠轮廓和姿态识别

### 6.2 SBTI 类视觉的传播机制

- 梗名负责爆点
- 熟悉动作负责记忆
- 一句毒舌负责转发
- 角色图像只负责把梗“钉住”，不承担全部解释

### 6.3 对 FocusTrail 的结论

**名字负责爆点，姿势负责记忆，颜色负责分类。**

单张人格卡不应同时使用多个强符号。上一版“混乱救世主”因元素过多而失去视觉重点。

## 7. 16 款 IP 统一画风

### 7.1 选定风格

采用原创的 **轻立体几何 IP**：圆润低多边形结构、轻纸雕 / 软陶质感、极简五官和柔和工作室光线。精致感来自造型、姿态、材质和阴影，不来自复杂装饰。

### 7.2 不变的角色基因

- 大圆头、短小圆润身体
- 两点式眼睛，无鼻子、无嘴
- 胸口使用 FocusTrail 正式“双端圆点＋中间弯曲轨迹”标记；中间必须是明显曲线，禁止简化成直线
- 黑、白、灰基础色
- 奶白色留白背景
- 柔和椭圆落地阴影
- 固定方形人格卡
- 左上人格代码、底部中文人格名
- 统一纸雕 / 软低多边形材质与灯光

### 7.3 家族色

16 型按代码前两位分成四个“注意力动力家族”。前两位决定用户通常如何启动和推进；后两位决定沉浸深度与偏离后的恢复方式。

### 7.5 组内四型的统一区分规则

四个颜色类别解决“属于哪一种推进家族”；第三、第四字母仍必须通过动作和空间关系表现：

| 代码位置 | 类型 | 视觉表达 |
| --- | --- | --- |
| 第 3 位 D | Deep 深潜 | 身体向内收、进入中心、纵向深入、色彩向核心加深 |
| 第 3 位 L | Light 轻切 | 身体展开、腾空、横向移动、轮廓更轻盈 |
| 第 4 位 R | Recover 回正 | 曲线重新接上主路线，身体或视线明确转回目标 |
| 第 4 位 M | Missing 迷航 | 路线断开、错向或被遮挡，角色未重新连接目标 |

因此统一性来自“同组色彩＋动作气质”，人格差异来自“独占物象＋D/L 姿态＋R/M 轨迹结局”。

## 8. 人格差异化设计规则

16 款不是“同一个黑色小人换道具”，而是同一世界中的不同角色。可使用以下六种设计手段：

1. **颜色设计**：用饱和度、集中度和流动方向表达爆发、均匀、深潜、轻切、回正和迷航。
2. **形象设计**：通过蒲公英、弹珠、火花、黑洞、云、潜水头罩等改变外轮廓。
3. **衣服设计**：潜水服、风帆式外套、运动服、节奏夹克、宽松毛衣等强化角色身份。
4. **场景设计**：每张只设置一个小舞台，如一段轨迹、圆形深水区、孤岛平台、小片云或三个节拍点。
5. **动作设计**：动作作为第一记忆点，直接表现回正、迷航、深潜、轻切、爆发或均匀。
6. **道具设计**：每款最多一个主要道具，用于把人格含义钉住。

### 8.1 “1＋2”差异化预算

每款使用：**一个主识别手段＋两个辅助变化**。避免颜色、服装、场景、动作和道具全部争夺注意力。

示例：

- 火箭蒲公英：主识别为蒲公英放射轮廓；辅助为轻质风衣、落回轨迹动作。
- 反向流星：主识别为单侧流星尾；辅助为掠过目标的姿态、回望动作。

### 8.2 16 款独占视觉锚点

除所有角色共有的 FocusTrail 曲线胸标和基础轨迹语言外，每款不得复用其他人格的核心物体、职业、服装轮廓或主动作。

- 唯一视觉锚点：**一枚落地后沿弧线弹回路线的橙红火花**；火花为紧凑实体轮廓，不使用流星长尾或烟花爆发造型。
- 造型设计：暖白运动短外套、炭黑袖裤与接地护膝，橙红细边延续 FB 点火组家族色；胸前使用 FocusTrail 两端圆点＋中间弯曲轨迹标记。
- 场景动作：角色单膝压低、身体向上回弹，一只手顺着回弹弧线指向火花，以“落地—回弹”的瞬间表现恢复力。
- v1 结论：动作张力和缩略图识别度成立，与火箭蒲公英、反向流星的轮廓均不重复。当前可作为 FBLR 正式首稿。
- 当前人格表达：**注意力乱跳，但还能自己弹回来。**

### 9.5 FBLM 走神弹珠

- v1：`04-fblm-distracted-marble-v1.png`
- 唯一视觉锚点：**一颗滚出轨道的高光橙色弹珠**；严格只保留单颗弹珠，不增加弹珠机或其他球形装饰。
- 造型设计：暖白圆领套头衫、炭黑短裤和圆头鞋，取消运动护具与外套，通过更松软的日常轮廓区别于 FBLR；胸前保留 FocusTrail 曲线标记。
- 场景动作：角色失去重心、跨步追赶已经滚离路线的弹珠，一只手向前伸出；用“越追越偏”的喜剧性动作表现低恢复力。
- v1 结论：单颗弹珠是清晰且独占的记忆点，服装、姿态与另外三款形成足够差异。当前可作为 FBLM 正式首稿。
- 当前人格表达：**一碰就偏，越滚越远。**

## 12. ADTI IP 的产品化：从测试人格到长期陪伴

2026-08-26 新增核心方向：ADTI 不能只是一张测试结果卡。用户完成测试后，对应人格应进入 FocusTrail，成为长期陪伴的个性化桌宠。由此形成完整闭环：

```text
ADTI 测试获客 → 领取专属人格桌宠 → 桌面专注陪伴 → 轨迹成长升级
→ 分享人格与等级 → 社群挑战与复测 → 数字商品 / 实体周边商业化
```

### 12.1 产品定位

桌宠不是单纯的聊天机器人，也不是只会播放动画的装饰角色，而是用户注意力轨迹的可视化代理：

> **你的注意力人格，住进桌面；看见你偏离，也陪你回到下一步。**

其差异化来自三层绑定：

1. **人格绑定**：桌宠由用户的 ADTI 四维结果决定，不是随机挑选皮肤。
2. **目标绑定**：桌宠知道用户当前正在执行的 FocusTrail 目标与“下一步”。
3. **行为绑定**：桌宠读取本地 Focus Sentinel 的桌面活动分类、进度与恢复状态，用动作和简短语言反馈。

因此，IP 不只是传播素材，而是产品界面、留存机制和商业资产的共同载体。

### 12.2 桌宠的五种实时状态

桌宠应复用现有 Focus Sentinel 的监测结果与任务上下文，不重复建设另一套分类系统。首期只需把既有数据翻译成角色状态：

| 状态 | 触发信号 | 桌宠表现 | 推荐反馈 |
| --- | --- | --- | --- |
| 待机 | 尚未开始 Focus Session | 安静停留，胸前轨迹微弱呼吸 | “今天要从哪一步开始？” |
| 专注 | 当前桌面活动与目标相关 | 沿轨迹稳定前进，进度环增长 | 默认不说话，避免打断 |
| 疑似偏离 | 出现一次短暂无关切换 | 看向侧边或轻微偏离轨迹 | 不立刻提醒，进入容错计时 |
| 确认分心 | 无关活动持续超过个性化阈值 | 人格专属偏离动作＋一次轻提醒 | “偏了吗？要回到下一步吗？” |
| 已回正 / 完成 | 用户返回目标或完成当前步骤 | 回到轨迹、点亮节点或短暂庆祝 | “回来了。下一步是……” |

关键原则：**监测不是每次切换都报警。** 短暂查资料、切换文档和休息可能服务于目标。提醒必须结合当前任务语境、持续时间与用户人格阈值，减少误报和通知疲劳。

### 12.3 人格化提醒策略

同一条“你分心了”不应对 16 型完全相同。首期不必制作 16 套复杂 AI，只需让四个轴控制提醒参数：

- **F / S（漂移 / 稳定）**：决定触发阈值。F 型允许更短的自然切换但关注连续漂移；S 型关注少见却较长的偏离。
- **B / E（爆发 / 均匀）**：决定节奏。B 型使用短冲刺、倒计时和检查点；E 型使用稳定进度与低频提示。
- **D / L（深潜 / 轻切）**：决定打断强度。D 型进入沉浸后尽量静默；L 型用更短、更轻的阶段反馈维持上下文。
- **R / M（回正 / 迷航）**：决定帮助深度。R 型只需一句提示；M 型应直接显示原目标与唯一“下一步”按钮。

人格 IP 同时用动作表达差异。例如：

- 火箭蒲公英偏离时会被风带走，恢复时尾部重新点亮。
- 反向流星冲过目标后回头，提醒用户确认当前方向。
- 弹跳火花短暂跳离后自动弹回，适合轻量提示。
- 走神弹珠越滚越远，需要更明确的“回到下一步”按钮。

### 12.4 桌宠界面 MVP

首期建议先做 **App 内桌宠**，验证有效后再升级为系统级悬浮桌宠：

#### 版本 A：App 内桌宠（近期可做）

- 位于 Focus Session 页面右下角，可收起。
- 头像 / 半身动作＋当前步骤名称。
- 一条环形或曲线形 Focus 目标进度条。
- 显示“专注中 / 暂时偏离 / 已回正”三种核心状态。
- 只提供一个主要操作：**回到下一步**。
- 直接订阅现有 Monitor SSE 事件，复用 `linkedTaskTitle`、活动分类和累计时长。

#### 版本 B：桌面悬浮宠物（中期）

- 透明、置顶、可拖动的小窗口；支持隐藏、暂停监测和免打扰。
- 用户离开 FocusTrail 页面后仍可看到目标进度与提醒。
- 点击桌宠展开迷你卡片：当前目标、下一步、剩余时长、回正按钮。
- 应以桌面壳或系统级小组件实现，普通浏览器网页不应宣称能够稳定完成跨应用置顶。

#### 版本 C：长期个性化陪伴（后期）

- 桌宠学习用户在不同场景下的有效提醒方式。
- 根据备考、写作、求职、编程等目标切换策略。
- 生成周轨迹故事，而不是只展示冷冰冰的统计表。
- 用户可复测或在行为显著变化时触发“人格迁移”，但不频繁更换身份。

### 12.5 隐私与信任边界

- 默认本地处理，优先使用应用名称、任务上下文和必要的窗口类别；不默认上传截图或完整窗口文字。
- 桌宠必须明确显示监测是否开启，并提供随时暂停按钮。
- 敏感应用沿用现有隐私过滤规则，跳过分类与记录。
- “分心”是相对当前目标的行为判断，不是对用户人格、疾病或自律性的评价。
- 不用羞辱、扣血或连续惩罚推动留存；产品的目标是缩短恢复距离，而不是制造焦虑。

## 13. Trail Level 用户成长等级

等级用于把“使用时间”转化为可见成长，但不能只奖励打开 App 或无限延长专注。建议等级经验称为 **Trail XP**，由三部分组成：

```text
Trail XP = 有效专注分钟 + 完成下一步奖励 + 成功回正奖励
```

- 有效专注分钟：只统计已开始 Focus Session 且与目标相关的时间。
- 完成下一步奖励：鼓励真实推进，权重高于单纯在线。
- 成功回正奖励：把“偏离后回来”定义为成长，而不是把分心当失败。
- 每日经验设置合理上限，避免为了升级而过度工作或挂机刷时长。
- 等级永久累计；连续打卡只提供轻量装饰奖励，不因断签倒退。

### 13.1 首版七级体系（阈值待种子测试校准）

| 等级 | 名称 | 建议累计有效专注时长 | 成长反馈 |
| --- | --- | ---: | --- |
| Lv.1 | 点亮 | 0–1 小时 | 领取 ADTI 人格桌宠，胸前轨迹点亮第一点 |
| Lv.2 | 上轨 | 1–5 小时 | 解锁基础表情与桌宠待机动作 |
| Lv.3 | 续航 | 5–20 小时 | 解锁人格专属恢复动作与一款背景 |
| Lv.4 | 回正 | 20–50 小时 | 解锁个人回正数据卡和分享徽章 |
| Lv.5 | 稳轨 | 50–120 小时 | 解锁角色服装细节或轨迹特效 |
| Lv.6 | 领航 | 120–250 小时 | 解锁高级周报外观与校园挑战身份标识 |
| Lv.7 | 造路 | 250 小时以上 | 解锁年度轨迹纪念物与共创 / 周边优先资格 |

这些阈值只能作为 MVP 起点。正式发布后应根据真实用户留存周期、每日专注时长与学生场景调整，不能把高等级等同于“更优秀的人格”。

### 13.2 等级与人格的关系

- **人格回答“你通常如何偏离与回正”**；等级回答“你和 FocusTrail 一起走了多远”。
- 16 型共用一套等级，不把某种人格设为高阶或稀有。
- 升级不改变人格代码，只让角色的轨迹、动作、服装小细节逐步成长。
- 隐藏款 Ø 的获得仍由行为模式变化触发，不能通过付费或刷等级获得。

### 13.3 免费版与 Pro 的边界

- 免费版：完整人格桌宠、核心监测状态、基础进度条、轻量提醒、Trail Level 和基础成长奖励。
- Pro：个性化提醒强度、更多桌宠动作 / 语气、长期轨迹报告、目标场景策略、跨设备同步和高级外观。
- 校园冷启动期延续 **3 个月 Pro 免费试用**，先验证桌宠能否提升回正率和留存，再决定正式价格。
- 不应把“停止提醒”“隐私设置”“回到下一步”等基础能力放入付费墙。

## 14. IP 商业化与差异化

### 14.1 IP 商业价值

FocusTrail 的 IP 壁垒不只是拥有 16 个可爱角色，而是：

> **每个角色都由真实注意力轨迹生成，并继续参与用户每天的执行与成长。**

这使角色同时承担：

- **获客入口**：ADTI 测试结果卡和人格梗图适合分享。
- **产品界面**：桌宠把监测、进度和回正提示变得可感知。
- **留存机制**：等级、动作和轨迹成长形成长期陪伴。
- **社交身份**：人格代码、家族颜色和等级徽章形成校园社群语言。
- **商业资产**：数字装扮、实体周边、校园联名和品牌授权。

### 14.2 分阶段周边计划

#### 阶段 1：低成本数字周边

- 人格结果卡、头像框、手机 / 电脑壁纸、聊天贴纸。
- Trail Level 徽章、考试季限定轨迹皮肤、桌宠动作包。
- 优先验证哪些人格最受欢迎、哪些文案最容易传播。

#### 阶段 2：预售制轻实体周边

- 贴纸包、徽章、亚克力立牌、钥匙扣、桌面目标卡。
- 采用校园活动现场预售或按需生产，避免一次性压库存。
- 先推出用户量与分享率最高的 4–6 款，而不是同时量产全部 16 款。

#### 阶段 3：核心高识别商品

- 人格毛绒、盲盒、桌面摆件。
- 与 FocusTrail 功能结合的实体专注计时器或 NFC“回到下一步”桌面按钮。
- 校园、考试季、求职季联名套装和品牌赞助款。

### 14.3 收入结构

```text
订阅收入：Pro 个性化能力与长期报告
+ 数字商品：皮肤、动作、限定主题
+ 实体周边：预售 / 按需生产 / 核心爆款
+ B 端合作：校园活动、机构联名、品牌赞助与 IP 授权
```

周边不应作为首期主要收入预测。路演中更合理的表述是：**先用 ADTI 获客、用桌宠提高留存、用 Pro 验证付费，再由真实人格热度指导周边开发。**

### 14.4 需要验证的关键指标

- 测试完成后领取桌宠的比例。
- 开启桌宠后 7 日 / 30 日留存变化。
- 桌宠提醒后的回正成功率与中位恢复时间。
- 各人格的分享率、收藏率和桌宠启用率。
- 等级到达率、升级周期和是否出现挂机刷时长。
- 数字周边领取 / 购买意愿以及实体周边预售转化。
- 桌宠提醒关闭率和误报反馈，验证陪伴是否变成打扰。

## 15. 产品路线优先级

1. **先做 App 内桌宠状态机**：复用现有监测事件，跑通“专注—偏离—回正—完成”。
2. **再做人格化提醒**：由四个轴控制阈值、节奏、强度和帮助深度。
3. **加入 Trail XP 与 Lv.1–Lv.7**：先验证成长体系是否提升留存，避免复杂装扮商店。
4. **验证后升级桌面悬浮宠物**：解决浏览器边界、系统权限与跨应用置顶。
5. **最后扩展商业化**：先数字周边与预售，再开发高成本毛绒、盲盒和硬件。
